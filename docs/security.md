# IAM policies and security configuration

The guiding rules:

* **Least privilege per workload.** Every compute component has its own role, scoped
  to named resources.
* **No long-lived credentials.** CI uses GitHub OIDC. Workloads use IAM roles.
  Database passwords are generated inside Secrets Manager and never appear in code,
  templates, CI logs or GitHub.
* **Defence in depth.** Network isolation, security groups, an application token,
  authentication, authorization, input validation and database privileges each
  limit the blast radius on their own.

## IAM roles

| Role | Assumed by | Can do | Defined in |
|---|---|---|---|
| `gqlapp-github-deploy` | GitHub Actions via **OIDC**, only for jobs in the `staging`/`production` **environments** of the configured repo | Create/update **only `gqlapp-*` stacks**; **pass only** the CloudFormation execution role; upload to the deployment bucket and `gqlapp-*-site-*` buckets; push to the one ECR repo; invalidate CloudFront; invoke `CodeDeployHook_gqlapp-*-migrate`; call **only `Query.health`** on AppSync (smoke test); snapshot `gqlapp-*` DBs. It cannot create IAM roles or touch resources directly. | `infra/bootstrap.yml` |
| `gqlapp-cfn-execution` | **CloudFormation only** | `PowerUserAccess` plus IAM restricted to roles named `gqlapp-*` and service-linked roles. All infrastructure changes go through CloudFormation and this role. | `infra/bootstrap.yml` |
| Lambda resolver role (`query`, `mutation`, `subscription`) | Lambda | `secretsmanager:GetSecretValue` on **the app_ro DB secret and the internal API token only**; VPC ENIs; logs; X-Ray. | `AppSyncInvokeRole` | AppSync | `lambda:InvokeFunction` on the three resolver functions (any version/alias), with `aws:SourceAccount` condition | `services/api/serverless.yml` |

| Flow-logs role | VPC Flow Logs | Write to the flow-log group | `infra/network.yml` |

Trust policies use `aws:SourceAccount` conditions where the service supports them,
to prevent confused-deputy access.

## Secrets and environment variables

| Secret | Created by | Rotation | Read by |
|---|---|---|---|
| RDS master (`dbadmin`) | RDS `ManageMasterUserPassword`, generated by AWS | **Automatic** (Secrets Manager managed rotation) | `migrate` Lambda only |
| `gqlapp/<stage>/db/app-rw` | `GenerateSecretString` in `database.yml` | Manual: rotate the value, then invoke `migrate` (it re-applies role passwords) and redeploy ECS | ECS (injected at task start), RDS Proxy |
| `gqlapp/<stage>/db/app-ro` | same | same; Lambdas pick it up automatically after an auth failure (cache reset + retry) | query Lambda, RDS Proxy |
| `gqlapp/<stage>/internal-api-token` | `GenerateSecretString` in `ecs.yml` | Manual: rotate, then redeploy ECS. Lambdas re-read it every 5 min. | Lambdas, ECS |

How values flow through the system:

* **Non-secret configuration** (hostnames, ARNs, sizes) moves as CloudFormation
  outputs: `${cf:...}` in `serverless.yml` and `Fn::ImportValue` in templates.
  Per-stage sizing lives in `infra/env/<stage>.env`, and per-environment settings in
  **GitHub Environment variables**.
* **Secret values** are never passed by the pipeline. Lambdas fetch them at runtime
  through the AWS SDK and cache them for 5 minutes. ECS resolves them at task start
  (`Secrets` with `valueFrom`), so they never appear in the task definition, image or
  logs.
* DB role passwords reach PostgreSQL as **SCRAM-SHA-256 verifiers**, computed
  client-side, so plaintext never appears in SQL text or database logs.
* The app logger redacts keys matching `password|secret|token|authorization|cookie`.

## Network security

| Source → Destination | Port | Rule |
|---|---|---|
| Internet → CloudFront | 443 | HTTPS only, `TLSv1.2_2021` with a custom domain, HTTP redirected |
| CloudFront → S3 | — | Origin Access Control (SigV4). The bucket blocks all public access and denies non-TLS. |
| Internet → AppSync | 443 | Cognito JWT required. IAM is allowed only on `Query.health`. |
| Lambda SG → internal ALB SG | 80/443 | Only the Lambda SG may reach the ALB |
| ALB SG → ECS SG | 4000 | Only the ALB may reach the tasks |
| Lambda SG, ECS SG → DB SG | 5432 | Nothing else can reach the database |
| DB SG ↔ DB SG | 5432 | RDS Proxy → instance |
| Lambda, ECS → internet | 443 | Through NAT, for AWS APIs (Secrets Manager, ECR, Logs, CodeDeploy) |
| DB subnets → internet | — | **No route**: the isolated route table has local routes only |

VPC Flow Logs capture rejected traffic. ECS tasks have no public IPs. The RDS
instance is `PubliclyAccessible: false`.

## Data protection

* **At rest:** RDS storage, snapshots and replica are encrypted with KMS. S3 buckets
  use SSE-S3. Secrets Manager uses KMS. ECR uses AES-256. CloudWatch Logs are
  encrypted by default.
* **In transit:**
  * Browser to CloudFront and AppSync: TLS.
  * Database: `rds.force_ssl=1`, and RDS Proxy has `RequireTLS`. Clients **verify**
    the server certificate against the RDS CA. Lambda uses `NODE_EXTRA_CA_CERTS=/var/runtime/ca-cert.pem`; the container bundles the RDS global CA.
  * Lambda to the internal ALB: plain HTTP inside the private subnets by default.
    For end-to-end TLS, pass `InternalCertificateArn`, `InternalDomainName` and
    `PrivateHostedZoneId` to `ecs.yml`; the URL output switches to HTTPS automatically.

## Application security

* **Authentication.** Cognito with authorization code + PKCE (public client, no
  secret), optional TOTP MFA, 12-character password policy, token revocation, and
  no user-existence leaks. Tokens are kept in `sessionStorage`.
* **Authorization.** The `owner` always comes from the verified JWT (`identity.sub`).
  Input objects are `strict()`, so a client-supplied `owner` is rejected. Every SQL
  statement is owner-scoped. The subscription resolver refuses subscriptions to
  another user's id.
* **API hardening.**
  * AppSync: query depth limit of 10, introspection disabled in prod.
  * Fargate server: POST only, 100 KB body limit, constant-time token check,
    landing page and stack traces disabled.
  * Unexpected errors are masked as "Internal server error" and logged in detail
    server-side.
* **SQL.** Only bound parameters, with column names from a fixed allow-list.
  `app_ro` can only `SELECT`; `app_rw` can only run DML. Neither can run DDL.
* **Browser.** HSTS (2 years, preload), a strict CSP (`script-src 'self'`,
  `connect-src` limited to AppSync and Cognito), `X-Frame-Options: DENY`, `nosniff`
  and `Referrer-Policy`.
* **Container.** Multi-stage build to a single bundle. `npm`, `yarn` and `corepack`
  are removed. The container runs as non-root (`uid 1000`) with a **read-only root
  filesystem** and an init process. Trivy gates CI on HIGH/CRITICAL findings. ECR
  scans on push, and tags are immutable.

## Hardening backlog (deliberately not enabled, mostly for cost)

* AWS WAF on CloudFront (pass `WebAclArn`) and on AppSync, with rate-based rules.
* Customer-managed KMS keys, for key-policy control and cross-account snapshot sharing.
* Automatic rotation for the app_rw/app_ro secrets, using a rotation Lambda plus a
  migrate call, or IAM database authentication. IAM DB auth is already enabled on the
  instance.
* Interface VPC endpoints (Secrets Manager, ECR, Logs) to remove the NAT dependency.
* Pin GitHub Actions to commit SHAs. Enable GuardDuty, Security Hub and CloudTrail
  data events at the account level.
